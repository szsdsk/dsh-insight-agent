# @deepseek-ai/dsh-insight-evidence

[English](README.md) | 中文

## 概述

搭配 InsightAgent 加载此包，可要求最终回答有查询证据，并提交有限范围的双期计划。只有同一 Agent 会话中成功执行的 `execute_sql`、`execute_analysis`、`diagnose_table` 或 `compare_tables` 查询通过校验后，其 `query_id` 才能支持 `submit_analysis` 中的结论。数值事实引用精确结果行列；插件根据保留的有限结果行核对数值，并在提交前重新检查源文件。Agent 结束时清除证据；后续会话必须重新运行并校验查询。

## 模型体验

### submit_analysis

#### 模型看到的内容

`submit_analysis` 接收答案、至少一条包含 `query_id` 的结论、可选的精确数值事实（`name`、`query_id`、从零开始的 `row`、`column`、`value`），以及假设和限制。结构化结果保留 SQL、数据源、校验状态、结果摘要和已核对数值；模型可见文本返回已接受的答案、查询 ID 和已核对数值。不存在、失败、过期、未校验、跨会话的查询 ID，以及越界或不一致的单元格会被拒绝。查询关联不会语义验证文字结论。

#### Token 影响

InsightAgent Preset 提供稳定的工具 Schema。计划和查询结果会将当前会话的证据加入后续模型请求；Agent 结束时清除这些状态。

#### KV Cache 影响

稳定的工具 Schema 可以复用模型请求前缀。每次结果会把当前会话的计划或查询详情加入后续请求，因此结果 Token 会随分析增长。

### 双期计划

#### 模型看到的内容

`submit_diagnostic_plan` 校验两个不同的数据源、1–32 个带依据的具名字段对应、1–3 个带定义的指标、最多两个维度、最多八个两期共用的分组范围过滤条件、可选键字段和 Top N。字段、维度、键和过滤条件均使用对应后的公共名称。每个指标返回两期值、变化和变化率。`execute_diagnostic_plan` 在比较前校验两期质量检查。阻断性数值问题返回 `status: blocked`、数量和定位样例，不接受为已完成运行，也不保存报告；用户可修正数据或确认修订计划。`drill_diagnostic_plan` 将两期筛选到已观测分组，再比较剩余维度，最多两层；拒绝选择汇总的 Other 分组。默认 `maxDiagnosticCorrections: 2` 在每条用户消息内允许首次提交或执行后的两次修正，无效提交也计数，修改计划不会清零执行次数；加载时只接受 0–5 的整数。`enableDiagnosticPlan: false` 在对照实验中移除诊断规划、下钻及任务工具。

#### Token 影响

计划增加有限的字段对应和指标定义。执行结果返回查询 ID、质量计数、总体指标，以及每个下钻结果最多十个分组；完整数据行可通过 `get_query_result` 获取。

#### KV Cache 影响

规划工具的 Schema 在多个回合保持稳定。提交的计划和执行结果会在请求后缀增加变化的 Token。

### 操作生命周期

#### 模型看到的内容

每个会话同时只接受一个诊断操作，与嵌套调用共用取消信号和 `diagnosticTimeoutMs` 时限。默认时限为 120000 ms，允许范围为 1000–600000 ms。超时和取消会拒绝尚未完成的操作；插件卸载会取消活动操作，并等待其结束。

#### Token 影响

被拒绝的重叠操作或超时会产生错误结果。取消的工作不会加入已接受的诊断结果。

#### KV Cache 影响

操作时限不会改变工具 Schema；错误会追加变化的结果文本。

### 可复用任务与报告

#### 模型看到的内容

`save_diagnostic_task` 将已成功执行的计划保存为用户指定的新名称，同时保存经过校验的 JSON 和离线 HTML 报告。`list_diagnostic_tasks` 读取工作区任务定义。`run_diagnostic_task` 接收确切名称或 ID 及两份替换 CSV/XLSX 路径，恢复区域与计算设置，重新登记数据源，检查对应字段，重跑并保存独立报告。缺失字段或不兼容数值类型返回 `status: needs_confirmation`、两份新数据源引用和发现的字段。用户确认并成功执行修订计划后，`update_diagnostic_task` 原子替换该任务配置，保留 ID、名称和历史报告。`save_diagnostic_report` 重新检查所有输入后，保存最近一次成功运行及其后续下钻结果。所有写入限定在 `.insight/diagnostics/`；返回工作区相对路径。报告使用共享的[离线渲染器](../../api/insight-controller/README.zh.md)。保存前调用 `submit_analysis` 会附上已接受的回答、查询关联结论、单元格校验事实、假设、限制及单列的业务解释。修订、重跑或进一步下钻后须重新提交；文字结论关联证据，但不会得到语义真实性校验。接受结果记录最近一次已记录模型请求的模型和供应商，不从配置标签推断两者。

#### Token 影响

列举任务返回保存的配置。重跑会将新的计划、数据源登记、查询结果和报告路径加入当前会话；列出的历史报告不会成为当前证据。

#### KV Cache 影响

任务与报告工具的 Schema 保持稳定。任务定义、替换路径和新结果在请求后缀中变化。

## 已知限制与待完成工作

- 证据只保存在运行中的 Agent 内存中。重启后仍可查看历史报告，但新的解释必须重新运行并校验查询。数值核对不能证明文字中的业务原因。
- 保存任务使用工作台的版本 1 文档，通过 Remote API 保留可选映射依据和指标定义，支持一个唯一键。字段对应及计算未变时，工作台编辑保留这些解释；更改对应或计算会清除相关解释。选择重名任务时须使用明确的任务 ID；保存新任务会拒绝已有名称。
- 保存先暂存全部新文档，再以独占方式发布完整文件。取消或发布失败时会回滚本次操作创建的文件，新任务保存不覆盖已有任务及报告。显式任务修订仅在数据源校验及修订计划成功运行后替换原配置。进程突然终止可能留下临时文件或部分发布的新文件，需要另行检查恢复。
- 不发布运行时不变量伴随模块；查询证据和诊断计划各自只有一份会话内权威记录。
